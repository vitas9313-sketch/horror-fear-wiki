# HORROR LAB｜Graph 生成指令

以下指令用於生成本專案的 Graph 設計草稿。Graph 只描述資料如何取得、整理、檢查與產生教學簡報，不直接取代來源查證，也不自動把未核實內容寫入 Wiki。

## 可直接使用的生成指令

```text
你是 HORROR LAB｜LLM Wiki 專案的流程設計助手。請依據專案中的 AGENTS.md、workflow/source-register.md、workflow/ingest-manifest.json，以及五篇 wiki 條目，設計一個「五篇研究整合成一份教學型 HTML 簡報」的 Graph。

教學主題：為什麼人會享受恐怖？
主要讀者：完全不熟悉恐怖心理與恐怖電影研究的初學者。

請先用黑暗恐怖哥德風格描述 Graph 的視覺概念：陰冷、低飽和、黑灰底色、暗紅色作為警示與進度色；畫面要克制、清楚、可讀，不使用血腥裝飾、過度花紋、閃爍動畫或難以辨識的文字。Graph 的每個節點仍必須以清楚的文字和箭頭表達，不得只靠氣氛圖形。

請建立以下節點，並為每個節點標示：輸入、處理、輸出、檢查者、失敗時返回哪一個節點。

1. 五篇 PDF 來源
2. PDF 檔案驗證：檔頭、格式、頁數、SHA-256
3. 研究重點整理
4. 證據類型標記：原始實驗、聲軌分析、理論文章、研究回顧、現場觀影研究
5. Wiki 條目
6. 五篇研究的概念關聯：聲音、預測誤差、恐懼／興奮、個人差異、Need for Affect
7. 教學簡報大綱
8. 人工大綱審核
9. 逐頁簡報內容
10. 主張與引用檢查
11. HTML 生成
12. 瀏覽器與可及性驗收

請明確畫出以下流程：
PDF 來源 → 檔案驗證 → Wiki 證據整理 → 概念 Graph → 教學大綱 → 逐頁內容 → 引用檢查 → HTML → 瀏覽器驗收

請加入回退邊：
- PDF 驗證失敗 → 回到來源檢查
- 主張沒有證據 → 回到 Wiki 證據整理
- 五篇資料之間的結論衝突 → 回到證據類型與限制檢查
- 大綱無法讓初學者理解 → 回到教學大綱
- HTML 顯示錯誤或文字不可讀 → 回到逐頁內容與版面設計

請在 Graph 下方補充 Loop 說明：哪些節點會重複執行、誰負責檢查、為什麼需要人工介入，以及哪一個節點最容易出錯。

請遵守：
- 不得捏造論文數據、案例、頁碼或引用。
- 理論文章不得寫成實驗結果。
- 回顧文章中的他人研究不得誤寫成回顧作者自己的實驗。
- 每個重要主張都要連回 Wiki 條目或來源 ID P-000 至 P-004。
- Graph 是可解釋的工作流程，不要加入沒有輸入輸出意義的裝飾節點。
```

## 本專案預期 Graph 的檢查重點

- Graph 應呈現「五篇來源整合為一份主簡報」，而不是五條互不相連的簡報流程。
- Paper 1、3、5 的數據節點要標為原始研究／分析結果。
- Paper 2 要標為理論框架與可檢驗命題。
- Paper 4 要標為跨研究回顧與限制整理。
- 最終輸出只有一份主要教學簡報；個別 Paper 簡報若保留，只能列為補充材料。
