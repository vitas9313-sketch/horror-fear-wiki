# HORROR LAB｜來源到教學簡報 Loop

## 流程

`取得資料 → 登錄來源 → 驗證檔案 → 受控 ingest → Wiki 整理 → 交叉查證 → 產生簡報 → 簡報驗收`

## 可重複檢查的節點

1. **來源登錄**：記錄作者、年份、DOI/URL、查閱日期與授權狀態。
2. **檔案驗證**：確認 PDF 標頭、頁數、SHA-256；錯誤頁面不得進入來源庫。
3. **受控 ingest**：只把已核對的五篇資料映射到 Wiki 草稿，不把 AI 文字當作來源。
4. **主張檢查**：每張投影片的主張回到至少一個 Wiki 條目與來源 DOI；遇到衝突並列而不硬選。
5. **瀏覽驗收**：檢查 HTML 可開啟、手機寬度可讀、鍵盤焦點可見、沒有外部資產依賴。

## 反思與調整

本次最常出錯的節點是「來源檔案驗證」：第一次使用錯誤 URL 時取得的是 404/Cloudflare HTML，而非 PDF。之後把 `%PDF-` 標頭與檔案大小檢查前移到 ingest 前，並以官方/機構頁面重新確認下載連結，再計算 SHA-256 與頁數。Graph 因此增加 `source → file-check → wiki-entry → slide-claim` 的可追溯關係；只有通過檔案檢查的來源才可進入後續節點。
